# Монитор здоровья — настольный прототип

### Фактическая цепочка данных

При синхронизации `DevicesWindow → DeviceManager → BluetoothConnector.fetch_metrics → LocalStorage.save_metrics`. При запросе отчета `ReportWindow → StatisticalDataAnalyzer.build_report → LocalStorage.load_metrics → Report → график/сводка`. Профиль идет по цепочке `ProfileWindow → ProfileService.validate/update_profile → LocalStorage.save_profile`. Это связывает четыре подсистемы, но ограничение хранилища по одному значению на показатель в сутки и демонстрационный connector выше мешают считать поток полностью соответствующим текстовому обещанию о необработанной истории измерений за любой период.

## Реализованные сценарии

- Главная показывает сегодняшние значения пульса, шагов, калорий и сна.
- Показатели отображает динамику за день, неделю, месяц или год, а также среднее, минимум и максимум.
- Профиль позволяет просматривать и редактировать имя, пол, возраст, рост и вес.
- Устройства позволяет подключать/отключать Smart Band 9 и Galaxy Watch 7; для подключенного устройства доступна демонстрационная синхронизация.
- После синхронизации формируются демонстрационные значения, которые попадают в локальную историю.

### Замеченные ошибки и пробелы диаграмм

- Sequence использует участника «Устройства» и русские названия операций, которые не совпадают с классами и методами базовой диаграммы классов.
- ER не выделяет профиль отдельной сущностью и не показывает явно датированные измерения/историю синхронизации; связи, кратности и модель «тип показателя — измерения» местами неоднозначны.
- BPMN перегружена ветвлениями и мелкими элементами, поэтому детали отдельных условий не всегда читаются.
- Use case требует ясной границы системы; связь `include` между просмотром динамики, выбором показателя/периода и построением графика не полностью пояснена.
- Диаграмма состояний UI местами не связывает переходы с операциями UI-классов и макетами загрузки/ошибки.
- Базовая диаграмма классов не везде показывает сигнатуры, атрибуты, кратности и использование интерфейсов; русский и английский языки имен смешаны.
- Диаграммы расширений ИИ и тренировок меняют `AppInjector` и `LocalStorage`, хотя заявлен принцип расширения без модификации базовых классов.

Эти пункты не исправлялись путем изменения предметной модели: реализация следует отчету настолько, насколько тот определяет поведение. Неописанные операции и ветви не трактуются как полноценные требования. Полный исходный разбор с оценкой серьезности находится в сохраненном файле анализа.

## Границы прототипа

Физический Bluetooth, облачная синхронизация, медицинская интерпретация и рекомендации ИИ в отчете не определены достаточно для настоящей реализации. Подключение и передача значений поэтому демонстрационные; данные не являются медицинскими. Настольная реализация выбрана по запросу пользователя, хотя исходные макеты визуально изображают мобильное приложение.
